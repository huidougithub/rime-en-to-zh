# 英译中选词复用接入（2026-10-22）

上游已经提供按输入串的个人选词排序和持久化。本次修复新增英译中路径的接入缺口，不建立平行存储，
不修改两次/三次自动造词和生词颜色门槛，不改词表、义项、配置默认值或随包资源。

## 行为与写入边界

`query/translation.rs` 只对当前完整英文词条的有效中文义项读取 `choice_weight`，稳定排序后保留原文退路。
`commit/translation.rs` 校验英文来源与当前组句一致、中文属于当前释义，再用原生 `commit_with` 提交。
不再借用英文源候选记词频，以免学习中文译义时改变英文补全。独立键 `en-zh:bank` 写入原有 `user-choices.tsv`；
这是一项累计选择记录（查询、中文、次数），不保存逐键序列、上下文或时间线。

平台先取走待确认 `TranslationChoice`，成功写入后才交回 Core。Windows 新协议 11 的回执仅包含会话、编号与布尔结果。
新增状态只管理尚未确认的提交，不是第二个学习器或存储层；排序和词库访问均留在 Core。
TSF 保持异步 `RequestEditSession`，受理成功不算文档成功。`commit_text` 返回成功后才设置确认标记；
此后拼音行更新失败不会撤销已成功写入的词。写入失败、请求拒绝、无上下文、编辑回调未执行、断连/丢失回执均不新增偏好。
重复回执不累加，其他会话不能确认它；学习关闭/私密输入不产生待学习选择，隐私状态变化可丢弃未确认记录。
回执在 Server 工人线程处理并调用既有原子写回，TSF 线程不在文档锁内读写用户文件。

保留原生累计次数语义：零历史的非首项选择一次就超过零次候选，不实现“任意最后一次选择覆盖全部历史”。
保留原生选择表的总量限制/衰减和清除学习数据功能。I/O 失败仍由原有学习器报告，未成功落盘不能保证重启保留。
当前功能只在 Windows 完成平台提交确认连接；其他壳未开启这个本地英译中配置，不宣称已接入个人排序。

## 自动验证

真实英汉源表的 `bank` 义项是“银行、河岸”。在隔离临时用户目录中测试：

1. 初始：`银行、河岸、bank`。
2. 选择第二项生成“河岸”，确认前累计次数仍为 0。
3. 成功回执一次后：`河岸、银行、bank`，原有文件出现 `en-zh:bank<TAB>河岸<TAB>1`。
4. 丢弃原 Router/Engine，重新装配并读取同一文件，仍为 `河岸、银行、bank`。这是自动重建状态测试，没有重启用户当前后台。另起两个独立 CLI 进程，读取该测试文件，均仍为“河岸、银行、bank”。
5. `BANK` 共用偏好；`right`、`set`、`studio` 与未知词保持各自来源；拼音、普通英文和其他学习表没有该译义计数。

另覆盖失败/丢失/重复/跨会话/关闭会话/旧 DLL 回执、取消与 Enter 原文、私密/学习关闭、伪造或过期候选、
陈旧选择表义项不能注入候选、鼠标点击路径、协议旧字段缺省和 TSF 客户端传递回执。
TSF 写入结果测试使用编辑函数故障注入，验证标记前失败/异常不确认、标记后拼音失败保留已写入结果；
未在用户真实文本框注入 COM 故障，未对所有应用做 GUI 验收。

## 组件与复现边界

源码中的隔离测试位于 `crates/qingjian-core/src/engine/tests/translation_choices.rs`、`apps/windows/server/tests/engine_loop/translation_learning/` 及 TSF 的 `commit_receipts` 测试。测试使用临时数据，不向真实学习表添加偏好。

部署须使用配套 Server 与 x64/x86 DLL；已加载旧 DLL 的应用需自行退出重开。选词成功回执和磁盘持久化分别验证；服务测试不代表所有 Windows 应用的文档写入均通过。新功能不需要开启输入日志、云服务或 API Key。通用步骤见 [更新边界](english-translation-choice-deployment.md)。
