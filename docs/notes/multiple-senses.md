# 本地多义项保留与兼容

上游基线：`db5d6fe325580fe49adf30b7bc8a7a786aafd4f3`。本分支取消读取与内存中的两义截断，保留显式格式兼容检查。

## 原因与各层行为

- TSV 本来是 `词\t[词性. ]译词[|读音]\t…`，没有两列义项的格式限制。旧解析器 `take(2)` 和 `Translation::new` 的 `truncate(2)` 会丢弃第三义。
- 个人释义读取与部分离线清洗、CC-CEDICT 导入也有两义截断；现已保留全部有效义项。个人文件仍是原来的 TSV，没有新增平行存储。
- `Translation` 仍用原有 `Vec<Sense>`，保留顺序、逐义词性与读音，没有把多个义项拼成一个字符串。
- `.qj` 的 `EntryRecord.sense_count` 原本就是 `u16`，每义独立一条 `SenseRecord`；布局不需加宽。旧构造器在映射读取后还会截断，因此必须用显式版本防止旧程序误读新多义数据。
- 英译中查询遍历全部义项，每个不同中文译词是完整可选候选，英文原文保持最后。去重保留首次义项及其词性，按原有个人选择次数稳定排序；集合仅用于避免义项多时的平方扫描。
- Windows 沿用原分页和按键；may 的“可能、可以、五月”是三个独立候选。普通英文/拼音旁的译文仍是辅助注记，既有第一、第二义快捷键不变；没有添加快捷键。

## 格式与升级

| 数据 | 新读器 | 新写器 | 旧读器 |
|---|---|---|---|
| 一义、两义 `.qj` v1 | 完整读取 | 仍写 v1 | 兼容 |
| 三义及以上 `.qj` v2 | 完整读取 | 自动写 v2 | 版本检查明确拒绝 |
| v1 声明三义及以上 | 拒绝错误的语义版本 | 不生成 | 不应使用 |
| 其他数据种类 | 沿用 v1 | 沿用 v1 | 不变 |

v2 只扩展释义表的语义契约，二进制记录布局不变；不能手改文件头冒充兼容。
TSV 的可变列语法保持兼容，但多义 TSV 需要新版解析器和转换器；旧工具对第三义不安全，发布使用新版转换器生成的 v2 `.qj`。
后续部署需要配套更新后台与英汉 `.qj`，保留其余全部正式资源、设置程序、配置及个人记录。IPC 仍为 11，Candidate 字段不变，现有 x64/x86 DLL 不需注册更新。
回退时恢复配套旧后台和旧英汉 `.qj`，不删除个人记录；词库未收录的旧偏好不会插入候选。

## 容量与范围

内存构造不再按少量义项截断。文件边界采用原布局的容量：每词最多 65,535 义、词/单义译词/读音各最多 65,535 UTF-8 字节，总字符串 arena 和义项记录索引为 32 位；超界明确报错，写入转换不再整数回绕。个人 TSV 加载沿用逐行容错：超界行跳过并告警，加载不会改写原文件；保存前的超界数据返回错误。读取检查版本、范围、UTF-8 边界和计数，32 位的范围计算也使用检查运算。

生成提示词仍建议每词 1–2 个常用义；这只是既有生成策略，解析与导出保留返回的有效义项。本轮没有发起生成请求或自动补写全库。只给已核实的 may 增加许可义“可以”，保留“可能”和“五月”，依次标 `v.`、`v.`、`n.`；`v.` 是现有粗粒度动词标签。大小写消歧和上下文选义不在本轮范围。

## 验证入口

相关 Rust 测试覆盖内存 1/2/3/129 义、重复译词、词性与顺序、v1/v2、格式边界、源表到 `.qj` 再到候选、三义分页、个人释义重载、一次选择前置及失败不计数。
`glossary::tests::every_real_source_glossary_round_trips_without_losing_senses` 按运行时源文件检查全部正式释义表，不把全表文本嵌入测试程序。
显式旧资源验证使用：

```powershell
$env:QINGJIAN_QA_LEGACY_DIR = '<public-v1-assets>\data\generated'
cargo test --offline --locked -p qingjian-translate legacy_packaged_glossaries_round_trip -- --ignored --nocapture
```

此测试只读公开随包资产，写入临时文件，并逐条比对旧 `.qj` 的完整义项。
自动验证使用隔离文件，不写入实际个人数据。转换完整性不等于全库语义准确率；没有人工审校保证。
